# 전산팀 업무관리 · IT WORKSPACE

관리자 설정의 사용자 관리에서 팀장 이름과 담당자별 퇴사 여부를 저장할 수 있습니다. 퇴사 처리 시 로그인 명단에서 제외하고 기존 로그인 세션을 종료합니다. 업무·통계·담당 당시 소속 기록은 유지하며, 퇴사 체크를 해제하고 다시 저장하면 로그인할 수 있습니다.

## 로그인 및 사용자 권한

접속하면 성명을 선택하고 비밀번호를 입력합니다. 직원 마스터에 등록된 모든 담당자의 최초 비밀번호는 `1`입니다. **이창주**는 관리자이며, 관리자 설정의 **팀장 이름**에 등록된 사람은 조회 전용 계정으로 자동 생성됩니다. 이창주는 관리자 권한을 우선 적용합니다.

- 관리자: 전체 업무 관리, 엑셀 업로드, 설정 변경, 보고서 확정, 사용자 비밀번호를 `1`로 초기화
- 담당자: 전체 조회, 본인 담당 업무 등록·수정, 본인 비밀번호 변경
- 팀장: 전체 조회, 본인 비밀번호 변경. 업무 등록·수정·업로드·보고서 저장은 화면과 API 양쪽에서 차단

화면 상단의 **비밀번호 변경**에서 현재 비밀번호와 새 비밀번호를 입력합니다. 비밀번호 변경 또는 관리자 초기화 시 해당 사용자의 다른 로그인 세션은 종료됩니다. 세션 유효시간은 8시간이며 서버 재시작 시 다시 로그인해야 합니다. 비밀번호는 소금값을 포함한 scrypt 해시로 파일에 저장되고 화면/API 응답에는 포함되지 않습니다. 관리자 설정의 **사용자 비밀번호 관리**에서 초기화할 담당자를 선택하세요.

이 로그인 추가는 로컬 프로그램에 적용한 것이며, 현재 서버의 `127.0.0.1` 접속 범위는 유지합니다.

## 참고 이미지 반영 및 공통 매핑

대시보드에 상태별 KPI 6개, 파트별 누적 막대, 상태 비율 도넛, 최근 4주 추이, 주요 진행업무·진행률, 공지사항을 적용했습니다. 통계 분석과 장비지원 분석은 저장된 실제 업무를 집계합니다. 진행률·시작일·요청부서·장비 종류는 업무 상세에서 입력할 수 있습니다. 공지 등록·수정·상단 고정·보관을 지원합니다.

**관리자 설정 → 엑셀 공통 매핑 사전 설정**에서 헤더 행, 필드별 컬럼, 담당자 확인 방식, 상태 매핑을 저장하세요. 개발자별 시트 양식이 같다는 전제로 한 번 저장한 설정을 모든 선택 시트에 공통 적용하며 다음 업로드에서도 불러옵니다. 업로드 화면에서 조정한 매핑도 관리자 설정에 저장할 수 있습니다. 컬럼은 실제 엑셀 순서대로 지정합니다(1열=A, 2열=B).

파트는 엑셀 파트 컬럼 대신 **관리자 설정의 직원별 소속 파트**에서 자동 결정합니다. 담당자 컬럼이 없고 시트명이 직원명과 같으면 ‘시트명 = 직원명’을 선택하세요. 미등록 또는 여러 파트에 중복 등록된 직원명은 검증 오류로 표시되며 임의 배정하지 않습니다. 기존 업무의 파트 스냅샷은 변경되지 않습니다.

DB 없이 JSON 파일에 저장하는 로컬 웹 프로그램입니다. 기존 예배 프로그램의 모던 다크 테마(#0D1420 / #192536 / #18A6A0)를 적용했습니다. 외부 서비스, CDN, AI 전송은 사용하지 않습니다.

## 실행

1. **start.bat**을 더블클릭합니다. Node.js 22 이상이 필요합니다. 현재 PC에서는 Codex에 포함된 Node.js도 자동으로 찾습니다.
2. 브라우저에서 http://127.0.0.1:4317 에 접속합니다. 처음 시작할 때 브라우저가 먼저 열리면 새로고침하세요.
3. 종료는 실행 창에서 Ctrl+C입니다. 서버 종료 후에도 저장 데이터는 유지됩니다.

패키지 설치 없이 실행됩니다. 명령줄에서는 `node server.mjs`, 검증은 `node --test tests/*.test.mjs`를 사용합니다. 포트는 환경변수 `PORT`, 저장 폴더는 `IT_DATA_DIR`로 변경할 수 있습니다. 주소와 서버 포트는 함께 바꾸세요.

## 구현 기능

- 통합·주간·월간 대시보드, 파트별 누적막대, 신규/완료/잔여 추세, 업무구분 분포와 지연 알림
- 업무 직접 등록·수정, 공동담당, 목표일, 보류 사유, 완료 후 재오픈 사유와 상태·활동 이력
- 등록일/활동일/완료 전이일과 상태 기준일을 분리한 집계 및 원본 업무 추적
- XLSX·CSV 업로드 → 시트 선택 / 공통 헤더·컬럼 매핑 → 검증·중복 후보 검토 → 행별 신규/갱신/활동/제외 → 확정
- 파일 SHA-256 재반영 차단, 원본 셀·시트·행 보존, 오류 CSV와 반영 취소
- 보고서 수동 작성·확정, 데이터 스냅샷 보존, JSON 다운로드, 인쇄/PDF
- 파트별 직원·업무구분 설정, 전체 JSON 백업 다운로드, 저장 시 자동 백업

## 파일 구조

```
server.mjs                로컬 HTTP 서버 / 저장·업로드 API
lib.mjs                   입력 검증 / 상태 기준일 / 집계
public/                   브라우저 화면 / 스타일
scripts/read-xlsx.ps1     Windows 기본 .NET ZIP·XML 엑셀 파서
tests/                    집계·이력·업로드 통합 검증
data/work-data.json       저장 데이터 (최초 실행 시 생성)
data/backups/             매번 저장 직전 전체 데이터 백업
```

데이터는 브라우저 저장소가 아니라 서버가 실행된 PC의 파일입니다. 브라우저를 닫거나 서버를 재시작해도 유지됩니다. JSON은 임시 파일을 완성한 후 교체하며 요청은 순서대로 저장합니다. 손상된 기존 데이터 파일은 임의로 초기화하지 않고 시작을 중단합니다. 동일 저장 폴더에는 서버 하나만 실행하세요.

## 엑셀 사용

XLSX는 Microsoft Excel 설치 없이 Windows PowerShell/.NET으로 읽습니다. CSV는 UTF-8만 지원합니다. 최대 파일 크기 10MB, 압축 해제 80MB, 전체 20,000행, 150열을 지원합니다. 암호화 파일·매크로 XLSM은 받지 않습니다. 매크로·수식을 실행하지 않으며 수식은 저장된 계산 결과만 읽습니다. 별도 악성파일 검사 엔진은 포함되지 않습니다.

개인별 시트·집계 시트 중 필요한 시트만 직접 선택합니다. 담당자는 등록된 직원명과 일치해야 하며 복수 담당자는 쉼표 또는 `/`로 구분합니다. 담당자명 별칭을 자동 추정하지 않습니다. 파트는 항상 관리자 직원 마스터에서 자동 반영하며 엑셀 파트 값은 사용하지 않습니다. `개발중→진행`, `처리완료→완료`가 기본 매핑이며 추가 상태는 `처리중=진행, 대기=접수` 형식으로 지정합니다. 분류 숫자는 초기 업무구분 순서(1~14)에 대응합니다.

제목·담당자는 필수입니다. 빈 등록일은 지정한 활동일, 빈 상태는 접수, 빈 분류는 기타를 사용하며 검증 화면에서 확인할 수 있습니다. Excel 날짜 일련번호와 YYYY-MM-DD / YYYY.MM.DD / YYYY/MM/DD를 지원합니다. 병합셀은 임의로 전파하지 않습니다. 모든 선택 시트에 적용할 공통 헤더 행을 선택하고 필요한 경우 원본을 정리하세요. 외부 업무ID와 동일 제목은 후보만 제시하며 자동 병합하지 않습니다.

반영 후 수정된 업무가 있으면 취소를 거부합니다. 후속 업로드를 먼저 되돌리거나 해당 업무를 직접 검토하세요. 배치·감사 이력은 취소 후에도 남습니다.

## 집계 규칙

고유업무는 ID별 1건, 파트 참여는 업무별 중복 없는 파트 수입니다. 취소는 기본 집계에서 제외합니다. 완료율은 기준일 상태가 완료인 건수 / 선택 기간 고유업무 수이며 0건은 `—`입니다. `완료 전이일` 기준은 해당 기간 완료 이력이 있는 고유업무를 선택하며, 이후 재오픈한 경우 기준일의 상태가 진행일 수 있습니다. 화면 상단에 기간과 기준을 항상 표시합니다.

추세의 신규는 각 구간 등록업무, 완료는 각 구간 완료 전이 고유업무, 미완료는 구간 말(기준일을 초과하지 않음)의 누적 미완료입니다. 월간 확정 보고는 필터와 문구 및 원본 업무 복사본을 보존합니다. CSV 내보내기는 Excel에서 열 수 있으며 수식 시작문자를 이스케이프합니다.

## 백업·복원·운영 범위

관리자 설정 → 전체 데이터 백업으로 내려받거나 서버 종료 후 `data` 폴더를 복사하세요. 복원은 서버를 종료하고 현재 파일을 별도 보관한 뒤 원하는 백업을 `data/work-data.json`으로 복사하고 재시작합니다. 자동 백업 보존기간은 아직 자동 정리하지 않으므로 필요에 맞게 관리하세요.

현재는 **127.0.0.1 전용 로컬 프로그램**이며 관리자·담당자·팀장 로그인을 지원합니다. 네트워크 공동사용과 파일 암호화는 포함하지 않습니다. 원본과 백업은 평문이므로 OS 폴더 권한으로 관리하세요. 사내 네트워크 운영은 접속 주소와 파일 잠금·백업 정책을 별도로 구성해야 합니다. 외부 AI는 연결하지 않습니다. 월간 서비스 결과보고서와 상세내역은 제공된 PPT·Excel 양식으로 생성합니다.

누적 업무일지 업로드는 기본적으로 선택 주차와 예정 업무만 반영합니다. 공통 매핑에서 주간구분 컬럼을 한 번 연결·저장한 뒤 반영 주차(예: 10월4주)를 확인하세요. 주간구분이 선택 주차/예정인 행 또는 상태가 예정인 행을 포함합니다. 파일의 가장 최근 주차를 제안하며 업로드 시 확인·변경할 수 있습니다. 전체 과거 자료를 최초 적재할 때만 해당 필터를 해제하세요.

대시보드는 조회 연도의 1월1일~12월31일 전체 현황을 보여주며 당해 연도는 오늘까지만 집계합니다. 주간·월간 화면은 업무현황 메뉴로 통합했고 상단에서 전환합니다. 주간 완료도 해당 기간의 완료일로 집계하므로 전월 완료는 포함하지 않습니다.

로그인 화면은 사용자 지정 참고 사이트 https://ilsancha.site/ichacare911/ 의 배경·화이트 카드·블루 버튼 구성을 반영했습니다. 배경은 public/assets/login-background.jpg로 보관하며 로그인 화면에서 외부 사이트에 접속하지 않습니다.


## 월간 서비스 결과보고서 및 근태

주간/월간 업무보고에서 월간과 보고 월을 선택한 뒤 **서비스 보고서 · 근태 (PPT/Excel)** 버튼을 누릅니다. 관리자가 주요 보고내용·이슈·근태를 검토하고 월별로 저장한 다음 PPT와 상세내역 Excel을 다운로드합니다. 다른 계정은 저장된 보고서를 다운로드할 수 있습니다.

근태는 관리자 설정의 팀장과 파트별 재직 인원을 기본으로 불러오며 자동으로 근무 처리하지 않습니다. 비상주 인원은 화면에서 추가합니다. 월별 입력과 내보내기용 업무 스냅샷은 데이터 파일의 monthlyServiceReports에 저장합니다. PPT 1장 양식을 유지하기 위해 보고내용은 15줄, 이슈는 3줄, 근태는 최대 18명까지 지원합니다.

보고 대상은 해당 월 완료와 기준일 현재 전체 미결입니다. PPT의 요청건수는 완료+미결, 진행중 건수는 예정·진행·보류를 포함하며 공동담당은 참여 파트별로 표시합니다. 상세내역은 같은 대상의 고유업무를 1건씩 표시합니다. 시행일자·현업담당자·예정일자는 원본 업로드 행의 열을 연결해서 읽으며 기본값은 제공된 양식의 7·11·13열입니다. 값이 없으면 공란으로 남깁니다.

배포 시 monthly-report.mjs, public/monthly-report-ui.js, scripts/export-monthly-report.ps1 및 report-templates 폴더를 함께 복사해야 합니다. Windows PowerShell/.NET ZIP XML 처리로 생성하므로 서버에 Office 설치는 필요하지 않습니다. 양식 파일에는 실제 업무·근태 값이 들어 있지 않습니다.

업무 등록·수정의 중요업무 체크는 Excel 빨간 제목과 같은 isMajor 값을 사용합니다. 주간·월간 주요내용에는 중요업무만 표시하며 월간 서비스 보고서의 기본 문구도 중요업무에서 제안합니다. 저장한 수동 문구는 유지하고 중요업무 다시 불러오기로 갱신할 수 있습니다.

보고서 작성 및 확정 버튼과 보고서 보관함 메뉴는 사용자 요청으로 비활성화했습니다. 기존 확정본 데이터는 보존하며 서비스 결과보고서·근태 PPT/Excel 기능을 사용합니다.

현업담당자는 업무 등록·수정과 Excel 공통 매핑에서 입력합니다. 업무목록의 별도 칼럼·키워드 검색·CSV 및 월간 상세내역 Excel에 반영됩니다. 기존 공통 매핑에서는 현업담당자 열을 연결한 뒤 다시 저장하세요.

누적 파일 업로드는 파일명 주차와 주간구분 예정 행, 보류 상태 행을 포함합니다. 보류 상태는 주차에 관계없이 포함하고 날짜 검사를 생략하며 상태 매핑에서도 보류를 유지합니다. 보류 사유가 없으면 엑셀 보류 상태 (사유 미기재)로 기록하고 원본 날짜·내용은 업로드 행에 보존합니다.


## HTML 업무등록

상단 HTML 업무등록에서 그룹웨어 HTML/HTM 파일(최대 2MB)을 선택합니다. 제목·본문·소속(요청부서)·기안자(현업담당자)·기안일(접수일)·문서번호를 추출한 뒤 기존 업무등록 화면에서 확인·수정하고 저장합니다. 파일명 날짜는 접수일로 사용하지 않습니다. 담당자는 로그인 사용자, 상태는 예정(접수)으로 기본 선택됩니다.

같은 문서번호의 기존 업무가 있으면 안내하며, 별도 업무임을 확인한 경우에만 같은 번호로 신규 등록할 수 있습니다. 팀장은 조회 전용입니다. 스크립트·이미지·외부 URL을 제거한 텍스트와 구조만 해석하며 첨부파일과 결재 도장은 가져오지 않습니다. 저장하는 것은 추출·확인한 항목과 출처 파일명입니다. 배포 시 public/groupware-html.js를 함께 복사하세요.

문서번호를 외부 업무ID에 연결하면 실제 번호는 보존합니다. 빈칸·내부문서는 신규 저장 시 INT-접수연도-업무고유값 형식의 자동번호를 부여합니다. 기존 업무 업데이트 시 빈칸·내부문서가 들어와도 기존 번호를 유지하며, 실제 문서번호가 새로 들어오면 그 번호로 변경합니다. 내부문서는 공통 ID 중복 판단에서 제외하고 제목·상세내용 일치를 확인합니다.
